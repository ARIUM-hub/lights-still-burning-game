# 《灯火未熄》独立命名流程设计

## 目标

将当前“标题页直接输入男女主名字”的交互，改为“进入剧情前先经过独立命名页”的流程，优先解决手机端命名入口不明显、用户误以为名字未生效的问题。

本次改动只调整原作故事的开场与继续流程，不改变剧情节点、结局结构、角色替换规则和 AI 工坊解锁条件。

## 选定方案

采用独立命名页方案。

标题页保留现有故事入口与功能按钮，但移除男女主输入框。用户点击 `开始故事` 或 `继续雨夜` 后，不再立刻进入剧情，而是先进入新的命名页；在命名页确认名字后，才真正开始新游戏或继续已有进度。

相比继续把命名区塞在标题页中，这种方案在手机端更聚焦，也更符合“先命名，再读故事”的心理预期。相比弹窗或抽屉方案，它的状态更清晰，不会和设置面板产生交互混淆。

## 界面流转

应用新增一个独立视图状态，用于承载命名页。调整后的主流程如下：

1. `标题页`
2. `命名页`
3. `剧情页`

具体规则如下：

- 点击 `开始故事`：进入命名页；命名确认后，从第一幕开始。
- 点击 `继续雨夜`：进入命名页；命名确认后，继续当前存档进度。
- 点击 `从头开始`：行为与 `开始故事` 一致，先进入命名页，再从第一幕开始。
- 命名页点击 `返回标题`：回到标题页，不改动当前剧情进度，也不保存本次未确认的名字修改。
- 已在结局页、回忆页、AI 工坊页时不额外插入命名流程；只有从标题页发起“开始 / 继续 / 从头开始”时，才进入命名页。

用户已明确要求 `继续雨夜` 也先经过命名页，因此不会为已有存档保留“直接进剧情”的快捷路径。

## 命名页结构

命名页延续现有雨夜视觉风格，但比标题页更收束，让用户注意力集中在输入与确认动作上。

页面从上到下分为三块：

### 标题区

- 主标题：`主角命名`
- 副文案：`先为这场雨夜写下他们的名字。`

### 输入区

- 第一项：`男主名字`
- 第二项：`女主名字`

布局规则：

- 手机端固定单列，男主输入框在上，女主输入框在下。
- 桌面端也保持上下排列，不再并排显示，避免弱化顺序感与填写引导。
- 页面进入后默认聚焦男主输入框，方便直接修改。

### 操作区

- 主按钮：根据来源场景切换文案
  - 新开局时显示 `带着名字开始故事`
  - 继续存档时显示 `带着名字继续雨夜`
- 次按钮：`返回标题`

命名页不承载声音开关、设置、回忆入口或 AI 工坊入口，避免页面职责混杂。

## 命名默认值与输入规则

- 两个输入框默认预填当前已保存的名字。
- 若是首次进入或旧存档缺少命名字段，则使用默认名 `小丑 / 小美`。
- 用户确认前，可自由修改两个输入框。
- 每个名字继续限制为最多 `12` 个字符。
- 不新增复杂校验，不要求必填；由于输入框已预填默认名，用户不改也可直接确认。
- 不提供单独的“恢复默认名字”按钮，避免操作区膨胀；若未来确有需要，可作为独立优化项再评估。

## 状态与存档设计

命名页使用本地页面状态承接输入，避免用户每输入一个字符就立刻改变应用全局状态或污染存档。

状态处理规则如下：

- 进入命名页时，从 `save.characterNames` 读取当前名字，初始化本地输入状态。
- 若存档来自旧版本且缺少 `characterNames`，继续复用现有存档兼容逻辑补默认值。
- 用户在命名页输入时，只更新命名页本地状态。
- 用户点击主按钮确认时，再一次性调用现有角色命名更新接口，把名字写回存档。
- 写回后，立即进入“开始新故事”或“继续当前进度”动作。
- 用户点击 `返回标题` 时，丢弃本次命名页内未确认的输入，不覆盖原存档名字。

这样可以保证“输入中”和“已生效”两种状态边界清晰，也能避免先前标题页实时写入导致的体验混乱。

## 对现有文本替换能力的要求

本次不重写角色替换逻辑，继续复用已经完成的名字替换能力：

- 剧情正文中的 `小丑 / 小美`
- 发言人名称
- 结局摘要
- 结局尾声
- 回忆页相关文案

命名页只是把“何时确认名字”从标题页实时输入，改为进入剧情前的一次确认。确认后的名字仍必须在以上所有位置统一生效。

## 组件与代码边界

推荐的代码边界如下：

- `App.tsx`
  - 新增命名页视图状态
  - 负责标题页、命名页、剧情页之间的流转
  - 根据入口类型决定命名页主按钮文案和确认后的动作

- `TitleScreen.tsx`
  - 移除现有男女主输入区
  - 保留现有开始、继续、从头开始、回忆、AI 工坊、声音、设置入口

- 新增 `NamingScreen.tsx`
  - 独立承载命名页 UI
  - 接收初始名字、模式类型、确认回调、返回回调
  - 内部维护本地输入状态

- `GameContext.tsx`
  - 保留现有 `updateCharacterNames` 能力
  - 不需要再为标题页实时写入提供特殊交互支持

- `global.css`
  - 新增命名页样式
  - 调整手机端布局优先级，确保命名页输入区和按钮区在窄屏下清晰可见

## 错误处理与兼容性

- 命名页返回标题时，不应意外重置当前存档进度。
- 旧存档继续兼容，缺少角色命名字段时自动补默认值。
- 若未来恢复标题页焦点管理，清除路线后回到标题页的原有焦点行为仍需保持。
- 若用户在“继续雨夜”前改名，后续剧情文本应立刻使用新名字，不需要重新进入节点或刷新页面。

本次不处理跨设备同步，也不引入新的网络请求。

## 测试与验收

需要覆盖以下测试：

### App 流程测试

- 无进度时点击 `开始故事`，先进入命名页，而不是直接进入剧情。
- 有进度时点击 `继续雨夜`，先进入命名页，而不是直接进入剧情。
- 有进度时点击 `从头开始`，先进入命名页，确认后从第一幕开始。
- 在命名页确认后才进入剧情。
- 通过命名页修改名字后，进入剧情立即显示替换后的文本。
- 在命名页点击 `返回标题`，回到标题页且不写入未确认名字。

### 命名页组件测试

- 男主输入框位于女主输入框之前。
- 页面默认展示预填名字。
- 主按钮文案可根据“开始 / 继续”模式切换。
- `返回标题` 回调触发准确。

### 存档与兼容测试

- 旧存档缺少 `characterNames` 时仍可进入命名页，并显示默认名字。
- 通过命名页确认后的名字会写入存档。
- 取消命名页不会覆盖原本存档中的名字。

### 回归验证

- `npm test`
- `npm run build`

## 不在本次范围内

- AI 故事工坊的后端代理接入
- 新增角色立绘或更多命名字段
- 命名页中的复杂输入校验、敏感词过滤或联网校验
- 不同故事线路使用不同角色名集合
- 跨设备同步名字配置

这些内容应在命名页流程落地并稳定后，再进入下一轮设计与实现。
