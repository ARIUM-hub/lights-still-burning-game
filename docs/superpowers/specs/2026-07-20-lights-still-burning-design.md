# 《灯火未熄》互动恋爱游戏设计文档

## 1. 产品目标

将短篇小说《灯火未熄》改编为一款手机优先、兼容电脑浏览器的单机视觉小说。玩家扮演“小丑”，在约 20–30 分钟的一次游玩中完成约 10 次关键选择。所有路线都保持原作的宿命悲剧气质；玩家无法得到传统圆满结局，但能改变错过的方式、关系破裂的原因，以及小丑多年后如何理解那个雨夜。

产品使用固定编写的剧情分支，不接入在线 AI、服务器或数据库。作品需打开即可游玩、断网可用，并在不同游玩路线中保持文学质量与结局判定的稳定性。

## 2. 体验原则

1. **选择不可轻易撤回**：首周目不允许回退，强化“说出口的话无法收回”的主题。
2. **属性完全隐藏**：不显示好感度、数值变化或系统提示，影响只通过后续叙事体现。
3. **悲剧并非同一种失败**：五个结局分别对应逃避、自我否定、猜疑、迟到和关系耗损。
4. **文学叙事优先**：采用视觉小说布局，但保留原作克制、冷静的旁白，不把作品做成数值养成界面。
5. **城市灯火是视觉隐喻**：画面始终明暗并存——城市很亮，但人物没有真正被照见。

## 3. 目标平台与体量

- 平台：现代移动端浏览器优先，同时响应式适配平板和桌面浏览器。
- 单次通关：约 20–30 分钟。
- 结构：五幕，每幕约 2 次关键选择，共约 10 次。
- 结局：5 个悲剧结局。
- 重玩：首周目通关后开放章节重玩与结局收藏。
- 网络依赖：无。剧情、插画、声音与程序均随站点发布。

## 4. 五幕故事结构

### 第一幕：雨落得很晚

场景包括咖啡店夜班、商场后门、旧公寓楼道。通过替班、客诉和与大壮的对话建立小丑“不会拒绝”的性格。选择主要影响勇气、自我否定，以及玩家是否愿意承认疲惫。

### 第二幕：有人看见了他

场景包括深夜便利店、雨中的地铁口和出租屋门口。呈现小美捡硬币、递热牛奶、送球鞋等情节。选择聚焦于小丑如何接受善意：坦率回应、礼貌回避，或因自卑直接拒绝。

### 第三幕：灯火中的阴影

小帅与小丽进入故事。朋友圈照片、顺路送行和白玫瑰共同推动小丑的猜疑。玩家决定是否向小美求证、是否听取小丽的劝告，以及是否把他人的善意解释成同情。

### 第四幕：明晚九点，南站

小美说明母亲病重与离开 A 市的计划，并邀请小丑同行。玩家面对是否表达感情、是否相信自己被选择、是否作出承诺等不可逆的关键选择。

### 第五幕：列车开走以后

时钟、未接来电、雨夜赶路和南站成为最后的叙事空间。玩家决定是否接电话、何时离开商场、是否前往南站，以及抵达后如何回应小美。剧情引擎依据关键行为和隐藏状态进入结局。

## 5. 五个结局

### 《列车已经开走》

原作路线。小丑在九点以后冲向南站，抵达时列车已经驶离。小美留下“我等到列车开走”的消息。

### 《无人接听》

逃避路线。小丑始终留在仓库，不接电话，也没有赶去南站。多年后，他仍会在便利店等待一个不会再亮起的名字。

### 《更好的人》

自我否定路线。小丑提前、明确地拒绝小美，自以为是在成全她。小美没有继续等待，而他后来才明白，那句“你会过得更好”只是替恐惧寻找体面的说法。

### 《站台两端》

猜疑路线。小丑准时抵达，却仍不相信自己会被坚定选择。他在最后的对话里追问小帅、金钱和未来，最终亲眼看着小美上车。

### 《下一座城市》

依恋与耗损路线。小丑跟随小美南下，但没有摆脱自我否定和过度牺牲。他不断压抑真实需求，最终在陌生城市里慢慢失去这段关系。该结局说明“握住一次手”不等于学会相信与相爱，仍然不是圆满路线。

## 6. 叙事状态模型

### 隐藏属性

- `courage`：勇气，代表表达需要、作出承诺和承担关系风险的能力。
- `attachment`：依恋，代表对小美及这段关系的情感投入；过低意味着疏离，过高且缺乏勇气时会形成失衡依赖。
- `selfDenial`：自我否定，代表将善意解释为同情、认为自己不配被选择的程度。

### 人物关系

- `xiaomeiTrust`：小美感受到的坦诚与信任。
- `dazhuangOpenness`：小丑是否愿意在大壮面前承认真实感受。
- `xiaoliAdvice`：小丑是否接受小丽关于表达与选择的提醒。

人物关系不在界面中显示，主要用于条件对白和场景变体，不单独决定结局。

### 关键事件标记

至少包含：

- 是否接受球鞋。
- 是否询问小美与小帅的关系。
- 是否接受小丽的白玫瑰。
- 是否向小美表达真实意愿。
- 是否承诺前往南站。
- 是否接起电话。
- 是否在九点前离开商场。
- 是否到达南站。
- 是否愿意同行。

关键事件标记优先确定结局候选，隐藏属性再决定同一候选路线中的对白、旁白和情绪强度。结局不得只依赖单一数值阈值。

## 7. 剧情组织方式

采用“五幕共享主线 + 条件变体 + 关键分岔”的混合结构：

- 各路线共享主要场景，确保原作节奏完整。
- 普通选择改变隐藏属性、人物关系和后续对白。
- 关键选择写入不可替代的事件标记，并在第四、第五幕形成实质分岔。
- 每个故事节点只描述当前内容、展示条件、状态影响和后继节点，不直接操作界面。
- 独立结局解析器根据事件标记与隐藏状态选择结局，便于测试全部路线。

## 8. 核心交互

### 剧情推进

- 玩家点击画面或“继续”区域推进旁白与对白。
- 支持逐字显示；玩家首次点击完成当前文字，第二次点击进入下一句。
- 关键节点显示 2–3 个选择，按钮位于移动端拇指易触达的屏幕下半区。
- 选择出现后必须明确点击选项，不设置倒计时。

### 首周目与重玩

- 首周目不提供上一步或回退选项。
- 每次选择后立即自动保存；刷新或关闭页面后可继续。
- 通关后解锁“雨夜回忆”，可从已完成章节的起点重玩。
- 章节重玩会创建新的当前路线，不覆盖已收藏的结局。

### 结局收藏

- 五个结局以车票残角形式展示。
- 未解锁结局只显示模糊轮廓，不显示具体达成条件。
- 集齐五个结局后解锁小丑多年后的隐藏独白。
- 收藏页不显示属性数值或路线攻略。

### 声音

- 首次播放声音必须由玩家主动开启，以满足浏览器自动播放限制。
- 包含雨声、便利店门铃、商场环境、城市车流和列车驶离等声音层。
- 提供始终可访问的静音按钮，并保存声音偏好。
- 声音关闭或播放失败时不影响剧情推进。

## 9. 视觉与界面设计

### 视觉方向

- 风格：电影感都市雨夜。
- 主色：深蓝黑、雾灰。
- 强调色：克制的琥珀暖光，用于便利店、路灯、车站时钟和关键按钮。
- 插画：为咖啡店、便利店、旧公寓、江边、商场仓库、雨夜街道和南站等关键场景生成统一风格的专属画面。
- 字体层级：旁白与重要对白偏文学感，系统信息与按钮保持清晰的现代无衬线风格。
- 动效：雨幕、灯光呼吸、对白淡入和轻微景深；尊重系统“减少动态效果”设置。

### 核心页面

1. **标题页**：作品名、主题句、继续游戏、从头开始、声音入口。
2. **剧情页**：全屏场景插画、顶部章节与设置入口、底部半透明对白框。
3. **选择状态**：画面略微压暗，2–3 个大尺寸选择按钮从下方出现。
4. **结局页**：结局标题、尾声、关键选择回望、进入收藏或重新开始。
5. **雨夜回忆**：车票残角式结局收藏、章节重玩入口、隐藏独白入口。
6. **设置面板**：音量、文字速度、减少动态效果、清除当前进度与恢复默认。

### 响应式与无障碍

- 以 375px 宽手机为最小重点尺寸，并适配平板与桌面宽屏。
- 桌面端限制文字行宽，不把长段旁白铺满屏幕。
- 所有触控目标至少 44×44 CSS 像素。
- 支持键盘推进、选择与关闭设置面板，并提供清晰焦点样式。
- 正文与背景对比度达到 WCAG AA；颜色不是唯一的状态表达方式。
- 逐字效果可关闭，减少动态效果时移除雨幕位移与大幅转场。

## 10. 技术架构

### 技术栈

- Vite
- React
- TypeScript
- 原生 CSS 或 CSS Modules
- Vitest 与 React Testing Library
- Playwright 端到端测试

不引入在线生成模型、后端框架或数据库。

### 模块边界

- `story`：结构化剧情节点、章节、角色与结局内容。
- `engine`：节点解析、条件判断、状态变更和结局解析。
- `state`：当前进度、设置、存档版本与结局收藏。
- `audio`：环境声加载、场景混音、静音与降级处理。
- `components`：场景舞台、对白框、选择面板、设置面板等纯界面组件。
- `screens`：标题、游戏、结局和雨夜回忆等页面级组合。

界面组件不得直接修改故事属性；所有选择统一交给剧情引擎处理。

### 数据流

`玩家选择 → 剧情引擎应用状态影响 → 写入事件标记 → 解析下一节点或结局 → React 渲染场景与对白 → 自动保存`

## 11. 存档与容错

- 存档包含明确的 `schemaVersion`。
- 自动保存当前节点、隐藏状态、事件标记、设置和已解锁结局。
- 存档损坏或版本无法迁移时，保留可验证的结局收藏与设置，只重置当前路线。
- 插画加载失败时显示同色系 CSS 雨夜背景，不显示破图图标。
- 音频加载或播放失败时自动静音，并保持游戏可继续。
- 剧情节点不存在或后继节点无效时，回到当前章节起点并显示简短恢复提示。
- 清除进度属于破坏性操作，必须二次确认；当前路线与结局收藏分开清除。

## 12. 测试与验收

### 自动化测试

- 属性变化、条件分支和事件标记的单元测试。
- 五个结局解析规则的表格驱动测试。
- 自动遍历剧情图，检查无效引用、不可达节点和非预期死路。
- 存档写入、读取、损坏恢复和版本迁移测试。
- 对白推进、选择按钮、键盘操作、静音与设置面板的组件测试。
- 首周目、刷新续玩、通关收藏、章节重玩和五结局可达性的端到端测试。

### 人工验收

- 在 375px 手机、常见大屏手机、平板和桌面宽屏检查布局。
- 检查触控目标、键盘焦点、文字对比度和屏幕阅读顺序。
- 检查减少动态效果、关闭声音和插画加载失败时的体验。
- 完整游玩至少两条明显不同的路线，确认对白变化与结局逻辑符合选择。
- 验证首周目约 20–30 分钟，且没有需要联网才能继续的内容。

## 13. 明确不在本期范围

- 在线 AI 动态生成剧情或对白。
- 用户自定义角色、题材或结局。
- 账号、云存档、排行榜、付费系统或社交分享。
- 多语言、配音和原生手机应用安装包。
- 明确的属性面板、好感度条、路线攻略或回退首周目选择。

## 14. 完成标准

满足以下条件时视为完成：

1. 五幕主线与约 10 次关键选择可完整游玩。
2. 五个悲剧结局均可通过不同选择抵达，并能正确收藏。
3. 首周目无回退，刷新后可从自动存档继续。
4. 关键场景具有统一电影感插画，环境音可开启、静音并正确降级。
5. 手机、平板和桌面布局可用，核心无障碍要求通过人工检查。
6. 剧情图、结局解析、存档和核心交互测试通过。
7. 断网环境下仍可完成整局游戏。
