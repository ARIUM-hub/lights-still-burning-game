# 《灯火未熄》GitHub Pages 部署设计

## 目标

将现有 Vite 单页游戏发布为长期可访问的公网 HTTPS 页面，目标地址为：

`https://arium-hub.github.io/lights-still-burning-game/`

页面必须能在桌面浏览器和手机浏览器直接打开，不依赖本地电脑持续运行。仓库将根据用户授权从私有改为公开。

## 选定方案

使用 GitHub Pages 与 GitHub Actions 自动部署。相比手动维护 `gh-pages` 分支，这种方式能让构建过程可追踪、可重复，并在以后更新代码时自动发布。临时公网隧道不采用，因为链接会依赖本地电脑在线。

## 架构

新增 `.github/workflows/deploy-pages.yml`，使用最小权限完成以下流程：

1. 检出代码并安装锁定版本的 npm 依赖。
2. 运行专用 Pages 构建，将 Vite 基础路径设为 `/lights-still-burning-game/`。
3. 上传 `dist/` 为 Pages 构建产物。
4. 使用 GitHub 官方 Pages 部署动作发布静态站点。

工作流响应当前功能分支与 `master` 的推送，并支持手动触发。这样可先从当前功能分支生成链接；部署提交合并后，后续 `master` 更新仍会自动发布。

## 项目改动

- 在 `package.json` 增加 `build:pages`，复用现有 TypeScript 检查并以仓库子路径构建。
- 新增 GitHub Pages 工作流，不改变业务组件、剧情数据和本地开发入口。
- 不引入新的运行时依赖、在线字体或第三方脚本。

本次改动仅涉及部署配置。根据用户批准，不为工作流 YAML 编写单元测试；以构建产物、GitHub Actions 状态和公网访问作为验收证据。

## 数据与访问

游戏在访问者浏览器内运行，存档继续使用 `localStorage`。不同手机或浏览器之间不会自动同步存档。静态页面不会把用户存档上传到 GitHub，也不需要登录或 API 密钥。

仓库公开后，源代码与剧情文本对所有人可见；这属于用户已明确接受的部署前提。

## 权限与安全

工作流只授予：

- `contents: read`
- `pages: write`
- `id-token: write`

部署不写入密钥，不使用长期访问令牌，不开放额外服务端接口。Pages 环境使用并发组，新的部署会替代尚未完成的旧部署，避免多次重复发布。

## 错误处理

- Pages 构建失败时保留 Actions 日志，不把失败版本发布到线上。
- 公网验证遇到临时网络异常时只做低频、有限次数检查，不循环刷新或批量重试。
- 若当前 GitHub 账户无法使用 Pages，则停止修改并报告具体限制，再由用户决定是否改用其他托管平台。

## 验收标准

- `npm test` 全部通过。
- `npm run build` 与 `npm run build:pages` 成功。
- Pages 构建产物中的脚本和样式 URL 都包含 `/lights-still-burning-game/` 前缀。
- GitHub Actions 部署任务成功完成。
- 目标 HTTPS 地址返回成功状态并显示“灯火未熄”。
- 在 375×812 手机视口下无横向滚动，开始按钮可见且可点击。
- 页面请求不依赖第三方运行时资源；插画缺失时继续使用现有 CSS 场景降级。

## 回滚

出现无法接受的问题时，可禁用 Pages、回退部署提交或重新运行最后一次成功的工作流。回滚不影响浏览器中已经存在的本地存档。
